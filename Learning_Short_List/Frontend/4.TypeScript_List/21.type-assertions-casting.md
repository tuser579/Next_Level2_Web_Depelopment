# 21. TYPE ASSERTIONS & 'AS CONST'

| Assertion Style | Syntax | Description |
| --- | --- | --- |
| `as Type` | `expr as HTMLInputElement` | Tells compiler to treat expression as specific type |
| Non-null Assertion `!` | `element!.textContent` | Asserts value is not `null` or `undefined` (use with caution) |
| `as const` (Const Assertions) | `const obj = { ... } as const` | Locks entire object/array into deeply readonly literal types |
| Double Assertion | `expr as unknown as Target` | Forced escape-hatch assertion through `unknown` |

**Example:**
```typescript
// 1. DOM Element Type Assertion
const searchInput = document.querySelector("#search-input") as HTMLInputElement;
console.log(searchInput.value); // ✅ Property 'value' exists on HTMLInputElement

// 2. Non-null Assertion Operator (!)
const mainContainer = document.getElementById("app")!; // Asserts app exists

// 3. 'as const' (Deep literal & Readonly assertion)
const API_ENDPOINTS = {
  USERS: "/api/v1/users",
  POSTS: "/api/v1/posts",
  AUTH: "/api/v1/auth"
} as const;

// Types are exact literals, not widened to 'string', and all keys are readonly:
// API_ENDPOINTS.USERS = "/changed"; // ❌ Cannot assign to 'USERS' because it is a read-only property

// 4. as const in Tuple Arrays
const supportedLocales = ["en-US", "es-ES", "fr-FR"] as const;
type SupportedLocale = typeof supportedLocales[number]; // "en-US" | "es-ES" | "fr-FR"
```
